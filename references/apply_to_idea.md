# Stage 4：用画像打磨用户的题目（02_apply_<idea-slug>.md）

输入：`01_taste_profile.md` + 用户的 idea（ideation 文件或用户描述：问题、洞见、方法、目前的结果）。
原则：**故事要为事实服务。** 选一个领域最买账、同时又完全真实的讲法；不能为了贴合口味去夸大方法做不到的事。

## 1. 品味体检

| 维度 | 用户 idea 的情况 | 画像里的对应规则 | 判断 |
|---|---|---|---|
| idea 来源类型 | 例：A12 组合 | R4：高档很少是纯组合 | ⚠ |
| insight 性质 | 关于方法 / 关于世界 | R2 | |
| gap 类型 + 有没有病因诊断 | | R3 | |
| 手上有没有自己的观察或初步实验可以当 OBSERVATION | | | |
| 最接近的反模式 | | §5 | |

结论只写三类：**顺风**（已经符合高档特征）、**可修**（换个讲法就能补上）、**结构性问题**（换讲法补不了，要改 idea 或补实验）。结构性问题要直说，并建议回到 research-ideation Stage 5/6，或者先补哪个实验。

## 2. 提炼一句话洞见

- 先写出用户 idea 现在的 insight 句（通常是"我们提出 X"）。
- 再按高档论文的写法改写 2–3 个版本，尽量变成**关于世界的论断**："X 之所以失败，是因为 Y；只要 Z，就能……"
- 每个版本都做"可证伪"检查：什么实验结果会推翻这句话？说不出来的不要用。

## 3. 生成 3 条故事线

从下面的叙事算子里选 3 个**彼此差别大**、并且在画像里有高档范例支持的：

| 算子 | 核心讲法 | 适用条件 |
|---|---|---|
| N1 现象先行 | 先给一个出人意料的观察，再解释、再利用它 | 手上有干净的观察或初步实验 |
| N2 假设挑战 | 指出大家默认的前提 Y 不成立，推翻它带来新方法 | 能用实验或例子证明 Y 不成立 |
| N3 诊断→处方 | 现有方法失败 → 病因 → 对症的方法 | 能讲清楚病因，而不只是症状 |
| N4 能力解锁 | 以前做不到的事，现在第一次能做到 | 真的能展示一个以前做不到的结果 |
| N5 统一视角 | 几种方法其实是一回事，统一后得到更好的方法或解释 | 统一要带来新预测或新方法，不只是换个说法 |
| N6 反直觉简化 | 复杂方法不必要，简单方法就够 | 简单方法确实打平或超过，而且消融实验干净 |
| N7 需求拉动 | 真实场景的约束决定了问题的形状 | 有真实数据、用户或部署约束 |
| N8 评测重审 | 现有评测量错了，换对的评测后结论改变 | 能证明结论真的变了 |

每条故事线都写满：

```markdown
### 故事线 A：<算子名> — <一句话>
- **一句话洞见**：
- **标题候选**：2 个（参考画像里高档论文的标题风格：冒号式 / 断言式 / 问句式……）
- **introduction 骨架**：
  - ¶1 [CONTEXT] 必须说：…… 参照范例：P07 ¶1 的开头方式
  - ¶2 [OBSERVATION] 必须说：…… 需要的证据：图 / 数字 ……
  - ¶3 [ROOT-CAUSE] ……
  - ¶4 [INSIGHT + APPROACH] ……
  - ¶5 [RESULT] ……
  - 贡献列表：3 条，每条可检验
- **Figure 1 草图**：类型 E_，画什么、左边是什么、右边是什么、读者 5 秒内应该看懂什么
- **证据债**：讲这个故事必须拿出的实验，标出"已有 / 需要补 / 两周内能否补上"
- **模拟审稿**：高档审稿人会夸什么；第一个质疑是什么（对照画像 §4、§5 和评审意见）；怎么提前在 introduction 里堵住
- **规则符合度**：符合 R_、R_；违背 R_（为什么可以接受）
- **包装风险**：这条线最容易在哪里讲过头
```

## 4. 比较与推荐

- 两两比较三条线：哪条更真实、更贴合画像、证据债更轻、更难被审稿人一句话驳倒。
- 推荐一条，也可以是组合（"用 A 的开头、B 的主线"），说清理由。
- 用户选定后再写完整 introduction。写的时候：
  - 句式和篇幅对齐画像里的高档惯例（段数、洞见出现的位置、话说到多满）
  - 每个需要实验支持的句子标 `[需证据: 实验名]`
  - 不照搬范例论文的原句，只借结构和技法
