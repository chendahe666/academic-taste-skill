# 拆解卡（每篇论文一张）

目的：把一篇 introduction 拆成**可以跨论文计数**的字段，再加少量只能靠判断的观察。分类字段一定要从下面的词表里选（可多选，但要标主次），不然 Stage 3 没法计数。

写卡时不知道这篇的档位（盲读）。不要因为作者有名、方法看起来复杂就高估，也不要因为英文不地道就低估；只看故事本身。

## 卡片模板

```markdown
# Pxx — <标题>
已识别：否 / 是（认出了这篇，知道它的出处或影响力）

## 1. 一句话
- **问题**（不用术语，一句话）：
- **key insight 原句**（引原文，≤25 词，注明 ¶ 编号）："..." (¶3)
- **insight 的性质**：关于世界的论断（可证伪的观察或假设）/ 关于方法的论断（"我们提出 X"）/ 两者都有
- **我的复述**：如果在 poster 前只能说一句话，作者想让你记住什么？

## 2. idea 从哪来
- **文中自述的来源**（原文怎么交代的，引 ¶）：
- **来源类型**（词表 A，主 / 次）：
- **推断的真实来源**：<判断> — 置信度 高/中/低 — 依据（点名的前作、raw/origins.md 里的作者访谈、时间线……）
- **前作谱系**：它主要站在哪 1–3 篇工作的肩膀上？是修补、反驳、迁移还是推广？

## 3. gap 怎么立
- **gap 类型**（词表 B，主 / 次）：
- **现有方法为什么不行**：作者只说了"做不到"（症状），还是说清了"为什么做不到"（病因诊断）？在哪一段？
- **gap 的证据**：引用 / 自己的实验或观察 / 一个例子 / 只是断言

## 4. 叙事结构
- **开头方式**（词表 C）：
- **逐段叙事步骤**（词表 D，一段可以有两个）：¶1 CONTEXT → ¶2 PRIOR+LIMIT → ¶3 ROOT-CAUSE → ...
- **洞见第一次出现在**：¶_ / 共 _ 段；**具体问题第一次被说清在**：¶_
- **篇幅**：_ 词，_ 段；有无小标题 / 加粗的段首 run-in
- **读者设定**：写给本子领域的内行 / 写给整个大会的听众（术语密度、背景铺垫多少）

## 5. Figure 1 与贡献
- **Figure 1 类型**（词表 E）：
- **Figure 1 承担的任务**：它自己能不能讲清楚这篇论文？
- **贡献列表**：有 / 无；条数 _；类型（方法 / 分析 / benchmark·数据 / 理论 / 系统·工具）
- **贡献是否可检验**：每条是否都对应一个能被实验证实或证伪的说法？

## 6. 话说到多满
- **强度**（词表 F）：
- **"first / novel / state-of-the-art" 类措辞**：_ 次；有无数字（"快 10 倍""提升 5 个点"）
- **许诺的证据**：introduction 许诺实验会展示什么？

## 7. 判断
- **这篇有意思在哪**（如果有）：对应 references/priors.md 里 Davis 的哪一类"反直觉"？
- **最弱的一环**：作为审稿人，你第一个会质疑的地方
- **值得偷的一招**：一个可以迁移到别的论文的具体技法（例如"用一个失败例子开头，¶2 马上给出病因"）
- **盲猜档位**：award / oral·spotlight / 高引 / 普通 poster / 被拒 — 置信度 _% — 理由（2–3 条，要具体到段落）
- **背景知识（和原文证据分开）**：你对这篇论文本来就知道的东西（若"已识别"）
```

## 词表

### A. idea 来源类型
| 代码 | 含义 | 常见信号词 |
|---|---|---|
| A1 现象驱动 | 观察到现有系统一个出人意料的现象或失败 | "we observe", "surprisingly", "we find that" |
| A2 假设挑战 | 质疑一个被普遍默认的前提 | "it is commonly assumed", "contrary to", "we revisit" |
| A3 跨域迁移 | 把别的领域的工具、概念、视角搬过来 | "inspired by", "borrowing from", "analogous to" |
| A4 统一 / 重构 | 把几种看似不同的方法放进一个框架，或换一种方式定义问题 | "a unified view", "we reformulate", "can be seen as" |
| A5 瓶颈拆除 | 找到限制性能 / 效率的那个瓶颈并去掉它 | "the bottleneck is", "dominated by" |
| A6 反直觉简化 | 证明简单方法就能打平或超过复杂方法 | "simple", "surprisingly simple", "without bells and whistles" |
| A7 规模 / 资源 | 放大数据、模型、算力之后出现了新能力 | "scaling", "at scale" |
| A8 新问题 / 新设定 | 定义一个新任务、新威胁模型、新场景（常由新技术或新需求催生） | "we introduce the task of", "a new setting" |
| A9 评测批判 | 指出 benchmark / 指标 / 协议有问题，给出新的 | "existing benchmarks fail to", "we find that metric X" |
| A10 理论解释 | 解释某个现象为什么成立，或用理论预测实践 | "we prove", "we explain why" |
| A11 需求拉动 | 来自真实应用的约束或痛点 | "in practice", "deployment", "real-world" |
| A12 组合 | 把 A 和 B 结合，并说出为什么结合有效（说不出就是反模式） | "combine", "integrate" |

### B. gap 类型
B1 能力（做不到）· B2 效率（太慢、太贵、太耗内存）· B3 鲁棒 / 泛化（换个分布就坏）· B4 理解（有效但不知道为什么）· B5 评测（量不准或量错了）· B6 假设不现实（现有方法依赖不成立的前提）· B7 新场景（旧方法没考虑过的设定）· B8 矛盾（已有结论互相冲突）· B9 可用性（需要真值、标注、专家调参等）

### C. 开头方式（¶1）
C1 宏大背景（"X has become ubiquitous"）· C2 具体失败例子 · C3 惊人的事实或数字 · C4 一个问题 · C5 类比 · C6 历史脉络 · C7 开门见山给出问题 · C8 直接给出发现或结论

### D. 叙事步骤（每段的作用）
| 标签 | 作用 |
|---|---|
| CONTEXT | 领域背景、为什么重要 |
| PROBLEM | 具体问题 |
| STAKES | 解决了会怎样，不解决有什么代价 |
| PRIOR | 现有方法 |
| LIMIT | 现有方法的不足（症状） |
| ROOT-CAUSE | 不足的原因（病因诊断） |
| OBSERVATION | 作者自己的发现、初步实验 |
| INSIGHT | 核心洞见 |
| APPROACH | 方法概述 |
| CHALLENGE | 把洞见落地时的技术难点 |
| RESULT | 结果、数字 |
| CONTRIB | 贡献列表 |
| SCOPE | 适用范围、限制、我们不做什么 |
| ROADMAP | 章节导航 |

### E. Figure 1 类型
E1 结果展示（teaser，好看的输出）· E2 问题 / 失败案例 · E3 新旧方法概念对比 · E4 方法流程图 · E5 曲线图（权衡、scaling、帕累托）· E6 现象 / 观察的可视化 · E7 没有图，或第一张图在方法章节

### F. 话说到多满
F1 克制（有限定、有边界、承认限制）· F2 平实（给数字，不渲染）· F3 自信（"significantly", "first"）· F4 夸张（宏大措辞超出证据）

## 写卡要点

- **症状和病因要分开。** "现有方法在 X 上表现差"是症状；"因为它们假设了 Y，而 Y 在 X 上不成立"是病因。很多领域里，高档论文和低档论文的差别就在有没有 ROOT-CAUSE 这一步。这是要检验的假设，不是结论，据实记录就好。
- **insight 句要找原文。** 找不到一句能当 insight 的话，就写"无明确 insight 句"，这本身就是重要信息。
- **推断来源要给依据。** 没有依据就写"无法判断"，不要编故事。
- **盲猜要在看档位之前写完**，写完不再修改。
